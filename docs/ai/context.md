# SmsChecker Context

## Purpose

SmsChecker — Android-приложение для постоянного прослушивания входящих SMS пользователя и дальнейшей обработки сообщений через настраиваемые каналы.

Приложение должно явно уведомлять пользователя о том, что сервис прослушивания SMS включен. Пользователь всегда должен понимать, что его входящие SMS прослушиваются приложением.

Проект развивается как pet-проект. Jira, MCP и внешние процессы управления задачами для него не используются, если пользователь явно не попросит обратное.

## Current State

- Root project name: `SmsChecker`.
- Базовый пакет приложения: `com.sms.checker.forwarder`.
- UI строится на Jetpack Compose.
- Архитектурная основа: Clean Architecture с MVI в presentation-слое.
- DI выполняется через Koin.
- Навигация строится через общий `Router` и feature-level `NavKey`.
- Локальное хранение организуется через Room.

## Product Behavior

- Приложение должно слушать входящие SMS пользователя в постоянном режиме, когда прослушивание включено.
- При включенном прослушивании приложение должно показывать пользователю уведомление об активном сервисе.
- Главный пользовательский контроль прослушивания находится на экране `feature-listening`.
- Пользователь должен иметь возможность включить или отключить прослушивание SMS через главный switch.
- Отдельные каналы обработки сообщений должны включаться и отключаться независимо друг от друга.
- Приложение не должно скрывать от пользователя факт прослушивания SMS.
- Отправка или пересылка SMS во внешние каналы должна происходить только через явно настроенные и включенные пользователем feature.

## Planned Features

- `feature-listening` — главный экран настроек прослушивания SMS и список всех доступных каналов обработки.
- `feature-email` — настройка пересылки SMS на email.
- `feature-telegram` — настройка пересылки SMS в Telegram.
- Другие похожие feature-модули могут добавляться позже как отдельные каналы обработки SMS.

## Feature Listening

`feature-listening` является первой основной feature приложения.

Экран должен содержать:
- главный switch в верхней части экрана, который показывает, включено ли прослушивание SMS;
- список дополнительных настроек и каналов обработки SMS;
- для каждого канала название, например Email или Telegram;
- switch у каждого канала, который показывает, включен ли этот канал;
- переход в отдельную feature настройки канала по клику на название или строку канала.

`feature-listening` отвечает за отображение общего состояния прослушивания и списка каналов, но не должна забирать себе внутреннюю логику настройки email, telegram и других каналов. Каждая такая настройка должна жить в своей feature.

## Structure

- `app/` — application-модуль, `MainActivity`, root-навигация, DI bootstrap и application-level `RoomDatabase`.
- `framework/` — базовые контракты и общая инфраструктура: `BaseViewModel`, `BaseUiState`, `Status`, theme-related общие элементы.
- `feature-*` — feature-модули. Каждый feature-модуль должен хранить свои `presentation`, `domain` и `data` слои внутри себя, если они нужны фиче.
- `build-logic/` — Gradle convention plugins.
- `gradle/libs.versions.toml` — единая точка хранения версий библиотек и Gradle-плагинов.
- `docs/ai/rules/` — архитектурные и командные правила для AI-агентов.
