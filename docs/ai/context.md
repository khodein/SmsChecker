# Context

## Purpose

Этот документ описывает продуктовый и технический контекст проекта `<project>`.
Он нужен AI-агенту, чтобы понимать, что именно делает приложение, и в какие архитектурные рамки укладываются изменения.

Документ — часть переносимого шаблона из `docs/`. Разделы помечены как:
- **(шаблон)** — заполняется индивидуально под конкретный проект;
- **(переносимое)** — общие правила работы AI-агента и архитектурный каркас, переносятся между проектами без изменений.

---

## Documentation Reading Rules (переносимое)

- Перед изменениями сначала прочитай `docs/AGENTS.md`.
- Затем прочитай этот файл, чтобы понять продуктовый контекст и текущие договоренности.
- После этого открой релевантные правила из `docs/ai/rules/` по зоне изменений: `architecture`, `structure`, `api`, `framework`, `screen`, `viewmodel`, `block`, `navigation`, `usecase`, `repository`, `db`, `di`, `dependencies`, `strings`.
- Если задача касается конкретной feature, сначала изучи существующую структуру этой feature и похожие реализации в других feature-модулях.
- Если документация противоречит текущему коду или задаче пользователя, не меняй архитектуру молча. Сначала зафиксируй противоречие и выбери минимальное изменение в рамках текущей задачи.

## Project Overview (шаблон)

Заполни под свой проект:

- **Name:** `<project>` (например, SmsChecker, Notes, Shop).
- **Root package:** `<root.package>` (например, `com.example.app`).
- **One-line purpose:** одно предложение, описывающее назначение приложения для пользователя.
- **Domain summary:** 2–4 предложения с описанием того, чем приложение занимается на доменном уровне (какие сущности, какие сценарии).

## Technical State (переносимое)

- UI строится на Jetpack Compose.
- Архитектурная основа: Clean Architecture с MVI в presentation-слое.
- DI выполняется через Koin (`object XModule { fun get(): Module }` для каждой фичи + корневой `AppModule`).
- Навигация строится через общий `Router` (`framework/router`) и feature-level `NavKey` + `Router.Provider`.
- Локальное хранение организуется через Room: application-level `AppDatabase` в `app/db/`, DAO и Entity — внутри feature-модулей (`feature-<name>/impl/db/`).
- Сеть — Ktor, изображения — Coil.
- Версии библиотек и Gradle-плагинов хранятся только в `gradle/libs.versions.toml`; группы зависимостей подключаются через convention plugins из `build-logic/`.

## Product Behavior (шаблон)

Опиши тут специфичное поведение приложения, которое нельзя вывести из кода:
- ключевые user-flow и инварианты;
- ограничения по приватности / разрешениям / фоновому исполнению;
- что приложение **не** должно делать (например, скрытые фоновые операции, отправка данных без согласия пользователя);
- какие сущности конфигурирует пользователь и где живут эти настройки.

Эти пункты — источник истины для бизнес-смысла фич. Если они противоречат коду, сначала спроси пользователя.

## Structure (переносимое)

- `app/` — application-модуль, `MainActivity`, root-навигация, DI bootstrap и application-level `AppDatabase`.
- `framework/` — базовые контракты presentation-слоя: `BaseViewModel`, `UiState`, `UiEvent`, `Status`, `BaseBlock`, тема (`AppTheme`) и общие UI-компоненты (`uikit`).
- `framework/router/` — навигационный контракт: `Router`, `Router.Provider`, `EntryProviderInstaller`, `NavTransition` (поверх Navigation 3).
- `framework/tools/` — служебные утилиты (`ResProvider`, форматтеры и т.п.).
- `feature-<name>/` — папка-контейнер фичи, состоит из двух Gradle-субмодулей:
  - `feature-<name>/api/` — публичный контракт фичи (router interface, domain-модели, `UseCase` interfaces, domain-исключения).
  - `feature-<name>/impl/` — реализация: `XModule`, router pair, presentation, domain, data, db.
- `build-logic/` — Gradle convention plugins (префикс `<prefix>.*`).
- `gradle/libs.versions.toml` — единая точка хранения версий библиотек и Gradle-плагинов.
- `docs/AGENTS.md` — контракт для AI-агента.
- `docs/ai/rules/` — архитектурные и командные правила для AI-агентов.

## Work Notes (переносимое)

- При изменениях сначала ориентируйся на существующую структуру проекта и правила из `docs/AGENTS.md` и `docs/ai/rules/`.
- Не добавляй новые библиотеки без явного разрешения пользователя.
- Если проект явно не использует внешние workflow (Jira/MCP/CI-конфигурации) — не подключай их без отдельного запроса пользователя.
- Соблюдай инварианты из раздела **Product Behavior**: они описывают то, что нельзя вывести из кода и что нельзя нарушать «по умолчанию».
